# Releases — Design

**Date:** 2026-06-23
**Status:** Approved

## Goal

Start publishing releases so existing (and prospective) users can see what's new.
Two parts:

1. **Fix the broken CI** — the `continuous` rolling release has failed on every
   run since the workflow was added (Feb 2026) and has never published anything.
2. **Add versioned (tag-driven) stable releases** with a CHANGELOG auto-generated
   from the project's Conventional Commits, keeping `continuous` as a second
   (bleeding-edge) channel.

## Root cause of the broken continuous release

The `build-rust` job runs `cargo build --release` / `cargo test --release` on
`ubuntu-latest` **without installing the Linux system dependencies**. It dies at
the first GTK/GLib `-sys` build script:

```
The system library `glib-2.0` required by crate `glib-sys` was not found.
The PKG_CONFIG_PATH environment variable is not set.
```

The `build-tauri` matrix job *does* install the deps (`.github/workflows/build.yml:57-60`),
but `build-tauri` and `create-release` both have `needs: build-rust`, so they are
**skipped** whenever `build-rust` fails — which is every run. So no artifacts are
ever produced and no release is ever published.

The `build-rust` job is also **redundant**: it compiles the whole app, then
`build-tauri` recompiles it again on Linux via `tauri-action`. Its only unique
value is `cargo test`.

## Decision: git-cliff + manual tags

Tooling choice (see alternatives in Out of scope): the maintainer keeps explicit
control over *when* a release ships. A version bump is performed by a script,
committed, and tagged; the tag push triggers CI to build + publish. CHANGELOG.md
and release notes are generated by **[git-cliff]** (Rust-native, conventional-commit
aware). No release-PR, no auto-bumping — releases happen on tag, not on merge.

[git-cliff]: https://git-cliff.org

## Architecture: restructured workflow

Replace the `build-rust → build-tauri → create-release` chain with four jobs.
The dependency graph gates builds on green tests and splits publishing by trigger:

```
push(main) ─┐                ┌─► continuous  (recreates `continuous` prerelease)
            ├─► test ─► build ┤
tag(v*)  ───┘                └─► release     (stable GitHub Release + cliff notes)
pull_request(main) ─► test ─► build   (no publish)
```

### `test` job (ubuntu only)

- Install Linux deps (`libwebkit2gtk-4.1-dev`, `libsoup-3.0-dev`,
  `libjavascriptcoregtk-4.1-dev`, `libgtk-3-dev`, `libssl-dev`,
  `libayatana-appindicator3-dev`, `librsvg2-dev`).
- `cargo test --release` (run in `src-tauri`).
- `npm ci` → `npm run check` (svelte-check — note: there is **no** `npm run lint`
  script in `package.json`).
- Fast-fail gate: `build` depends on this.

### `build` job (matrix: ubuntu / macos / windows)

- `needs: test`.
- Matrix mirrors the current one: ubuntu (deb + AppImage), macos
  (`--target universal-apple-darwin`, dmg), windows (msi + exe).
- Per-OS: install Rust toolchain (+ macOS universal targets), install Linux deps
  (ubuntu only), `npm ci`, `tauri-apps/tauri-action@v0` build, upload artifacts
  (`*-artifacts`).
- Runs on PRs too (no release consumed).

### `continuous` release job

- `if: github.event_name == 'push' && github.ref == 'refs/heads/main'`.
- `needs: [test, build]`, `permissions: contents: write`.
- Downloads all artifacts (merge-multiple), recreates the existing `continuous`
  prerelease via `dev-drprasad/delete-tag-and-release` +
  `softprops/action-gh-release@v1` (`prerelease: true`,
  `generate_release_notes: true`). Behavior preserved from today — just finally
  fed real artifacts.

### `release` job (tag-driven)

- `if: startsWith(github.ref, 'refs/tags/v')`.
- `needs: [test, build]`, `permissions: contents: write`.
- Downloads all artifacts.
- Generate the release body with **git-cliff** (in CI, via the
  `orhun/git-cliff-action`):
  `git cliff --latest --strip header` → the latest version's notes only.
- Publish a stable GitHub Release (`softprops/action-gh-release@v2`,
  `prerelease: false`) tagged at the pushed tag, attaching all platform binaries.

### Triggers

```yaml
on:
  push:
    branches: [main]
    tags: ['v*']
  pull_request:
    branches: [main]
```

## Version sync — `scripts/bump-version.sh <x.y.z>`

Versions live in three files (all currently `0.1.0`):

| File                          | Field             |
| ----------------------------- | ----------------- |
| `src-tauri/Cargo.toml`        | `version = "…"`   |
| `package.json`                | `"version": "…"`  |
| `src-tauri/tauri.conf.json`   | `"version": "…"`  |

The script updates all three atomically so they never drift, then:

1. Bump the version in the three files (idempotent `sed` replacements).
2. `cargo generate-lockfile` to refresh `Cargo.lock` (commit if changed).
3. `git cliff --unreleased --prepend CHANGELOG.md` to regenerate the changelog.
4. `git add` the changed files + `CHANGELOG.md`, commit
   `chore(release): vX.Y.Z`, tag `vX.Y.Z`.
5. **Does not push** — print the `git push --follow-tags` instruction for the
   maintainer to run after review.

`set -euo pipefail`; validate the argument is a semver `MAJOR.MINOR.PATCH`;
refuse if the working tree is dirty or the version is unchanged.

## CHANGELOG — git-cliff config

- New file **`cliff.toml`** at repo root: conventional-commit parser.
  Group mapping: `feat`→Features, `fix`→Bug Fixes, `perf`→Performance,
  `refactor`→Refactor, `docs`/`chore`/`style`/`test`/`ci`→Miscellaneous.
  Header format: `## [X.Y.Z] - YYYY-MM-DD`. Filter out merge commits.
- New file **`CHANGELOG.md`** (generated, **committed** to the repo so people can
  browse history without leaving GitHub).
- **Bootstrap:** with no prior tags, the first `git cliff` run generates the full
  historical changelog from the very first commit.

## Release flow (manual control)

```bash
./scripts/bump-version.sh 0.2.0      # bump 3 files + CHANGELOG + commit + tag
git push --follow-tags origin main   # CI builds all platforms + publishes the stable release
```

## Two channels

| Channel       | Trigger        | Tag             | Stability     |
| ------------- | -------------- | --------------- | ------------- |
| `continuous`  | push to `main` | rolling `continuous` (recreated each push) | preview / bleeding-edge |
| stable        | tag `vX.Y.Z`   | immutable version tags | stable releases |

## First stable release

Default: **`v0.1.0`** (the current version) — marks "first public stable release
with proper releases + changelog". Revisable: if the maintainer prefers to signal
a milestone, `v0.2.0` is equally valid. Either way the bootstrap run emits the
full historical CHANGELOG.

## Known unknowns (set expectations)

- The **macOS** (`--target universal-apple-darwin`, `.dmg`) and **Windows**
  (`.msi`/`.exe`) builds have **never run** — they were always skipped behind the
  failing `build-rust` job. The Linux path and the CI blocker are fully resolved
  by this design. The first `main` push after this lands will reveal whether the
  macOS/Windows builds succeed; if either fails, fix per-platform at that point.
- `tauri-apps/tauri-action@v0` is currently pinned at `v0` in the existing
  workflow; the release job will use `@v2` of `softprops/action-gh-release`. Both
  are stable and current.

## Out of scope (YAGNI)

- **In-app update notifications (Tauri updater)** — requires a signing key,
  release JSON hosting, and Rust/Svelte changes. Separate effort; not now.
- **release-please / auto-bumping** — would remove manual control and add a
  release-PR concept; rejected in favor of explicit tags.
- **Code signing / notarization** (macOS notarization, Windows Authenticode) —
  not required to publish; can be added later when a signing identity exists.
- **No committed CHANGELOG / notes-only** option — rejected; a browsable
  in-repo CHANGELOG is part of the goal.
